What This App Does

A user drops a messy Excel file onto the page. The Python backend scans it and returns diagnostics. The user picks cleaning rules, then clicks Clean My Spreadsheet. While the cleaning mascot animates (at least 3.5 s), the backend runs pandas transformations. When done, the frontend shows a before/after summary, an enriched audit log (per rule: cells changed + examples), and a download button for the cleaned .xlsx.

Everything runs locally — no user accounts, no cloud storage. The file is processed in memory and never written to disk.

Reference Route — Follow "Clean My Spreadsheet"

This is a reference route built from the finished code. It was not walked through interactively.

1
Entry point — frontend/src/App.jsx, handleClean
When the user clicks the button, handleClean builds a FormData object with the file, the selected options (as JSON), and any custom instruction. It fires two things in parallel with Promise.all: the real POST /api/clean fetch and a 3.5 s timer — so the mascot always plays fully before results appear.
See the relevant lines 
// App.jsx  ⟶  handleClean
const minAnimationDelay = new Promise((r) => setTimeout(r, 3500));
const [response] = await Promise.all([
  fetch('/api/clean', { method: 'POST', body: formData }),
  minAnimationDelay,
]);
setResults(data);   // triggers AuditLogResults to appear
2
Logic — backend/cleaner.py, clean_excel
The function receives the raw file bytes, runs up to six pandas transformations in order (duplicates → empty rows → empty cols → headers → whitespace → fill numbers), and builds two lists: what_changed (enriched dicts with rule name, cell count, examples) and what_didnt_change (plain strings). The cleaned dataframe is serialised back to .xlsx bytes and base64-encoded for transport.
See the return shape 
return {
  "status": "success",
  "original_rows": ..., "new_rows": ...,
  "duplicate_rows_removed": ...,
  "missing_cells_before": ..., "missing_cells_after": ...,
  "what_changed": [           # ← list of dicts
      { "rule": "...", "summary": "...",
        "cells_changed": N, "examples": [...] }
  ],
  "what_didnt_change": [...], # ← list of strings
  "file_base64": "..."        # ← the cleaned .xlsx
}
3
Result — frontend/src/components/AuditLogResults.jsx
Once App.jsx sets results, AuditLogResults renders the before/after summary bar (rows in → duplicates removed → rows out → missing flags), then one card per rule in what_changed with an inline example table. The download button calls back to handleDownload in App.jsx, which decodes the base64 string and creates a temporary <a> element to trigger the browser download.

"To Change This, Start Here"

backend/cleaner.py → Add or tweak a cleaning rule (e.g. drop columns with >80 % missing).
frontend/src/App.jsx — handleClean → Change the minimum mascot display time (look for the 3500 ms literal).
frontend/src/components/AuditLogResults.jsx → Add, remove, or reorder summary stat cards; tweak example table columns.
frontend/src/index.css → Change the cream background colour (#f6f1e5), grid lines (#d3c6ae), or animation keyframes.
backend/gemini_helper.py → Change how the custom instruction text is sent to Gemini, or swap in a different model.
tailwind.config.js → Rename or add palette colours (parchment, wood, spruce, …) used throughout the UI.

How to Run It Again

Backend (from project root)

.\backend\venv\Scripts\python -m uvicorn main:app --app-dir backend --port 8000 --reload

Frontend (new terminal, from project root)

cd frontend npm run dev

Then open http://localhost:5173 in your browser. The frontend proxies /api/* to :8000 automatically (configured in frontend/vite.config.js).

Run backend tests

.\backend\venv\Scripts\python -m pytest backend/test_api.py -v

A Practice to Reuse

Parallel fetch + timer → predictable UX.

In App.jsx handleClean, the API call and a fixed timer run side-by-side with Promise.all. The UI only advances when both finish — so the mascot always plays for its full 3.5 s, no matter how fast the backend responds.

The pattern — pair a real async task with a minimum-wait promise — is reusable any time you want a loading state to feel intentional rather than flickering. It requires no extra library; just Promise.all([realFetch, minDelay]).
