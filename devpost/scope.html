Scope · approved · proof of concept

Messy Data Helper

An app that takes a messy Excel file, shows what’s going on, asks before it changes things, then hands back a tidier file plus a log of what changed and what didn’t.

The unique kernel

Trust. Without questions before changes and a clear log of what was (and wasn’t) changed, people would not trust it enough to use. The human stays the evaluator so meaning isn’t lost and insights aren’t invented.

Who it’s for

Someone like you during the internship: a messy Excel file lands, hours or days go into cleaning it in Excel, then insights go to a supervisor. You want a first pass so you are not starting from a blank, terrifying spreadsheet — and you still need to catch mistakes that could distort decisions.

Other people in “data for decisions” work are a later hope, not the first person to design for.

User, loop, and proof

Intern with a messy Excel file → breakdown and questions → optional instructions or a basic tidy → change log and download. The proof is that the log and questions make the file trustworthy enough to take.

Core loop, in order

1

Give the app a messy Excel file.

2

See a breakdown of what’s going on: rows, columns, missing values.

3

Answer prompts on what to change or not, with a place for extra instructions.

4

If you skip extra instructions, it does a basic organization and overview.

5

Download the same data as a tidier CSV or Excel file, with a log of what changed and what did not.

You come back because the next file is also messy, and you still don’t want to start from scratch.

What “working” looks like

On a screen, in about a minute: drop in a messy Excel file → see the breakdown and the questions → optionally type instructions (or skip) → get a basic organized file and overview → see the log → download.

The “oh, that’s cool” beat is the log plus the questions — enough trust to take the file — not a full insight report.

Identity

Not a chatbot. Not a generic AI-looking site. Not Excel, Tableau, or Power BI. Visually appealing but clean.

A cartoon character is the “owner” who takes the work. For this proof of concept it only appears while explore/process/clean is running, until results come back. Broom-and-sweep motion is later.

Why this matters

Internship messy Excel took hours or days before insights were even possible. You want to fear messy data less, keep a human check so bad cleaning doesn’t cost money, and eventually make something other people might use as a data/digital product. This hackathon is the working first slice, not the business.

Now, later, cut

  • One file type: Excel
  • Breakdown: rows, columns, missing values
  • Prompts on what to change or not, plus a place for extra instructions
  • If no extra instructions: basic organization and overview
  • Downloadable tidier CSV or Excel of the same data
  • Log of what was changed and what was not
  • Subtle cartoon character only while processing
  • Insight report, charts, and visuals of the data
  • In-app end-to-end path (edit inside the app, full report)
  • Any data type beyond Excel
  • Richer cartoon (broom, sweeping files, stronger mascot)
  • Something other people pay for as a digital product
  • Chatbot / non-interactive generic AI look — wrong feel
  • Excel / Tableau / Power BI interface clone — wrong identity
  • Full commercial product and “does this already exist” research — not a 2–4 hour proof of concept
